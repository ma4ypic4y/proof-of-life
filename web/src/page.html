Computational Life, replayed on a Mac mini

Life copied backwards

Fill a world with random programs, let them collide and rewrite each other, and self-replicators appear on their own. We watched them appear in dozens of worlds. Almost every time, they copied themselves in reverse, so each species lives as a pair of mirror strands.

The setup

Ten instructions, no goal

The world is the BFF soup from Agüera y Arcas et al., “Computational Life” (2024): 131,072 tapes of 64 random bytes. Each epoch, tapes are paired at random, glued into one 128-byte tape, run for up to 8,192 steps, and split back. Of the 256 byte values, ten are instructions. Code and data share the tape, so running programs rewrite each other. Nothing selects anything.

We rebuilt Google’s reference simulator, cubff, as a single C file that is 4–5× faster on a CPU and produces the same soup byte for byte (checked on 150 snapshots, four regimes). Then we ran world after world on a Mac mini, each for up to 16,384 epochs.

Atlas of origins

Every origin, backwards

Copying backwards has a consequence. The child of + is its mirror image −, and the child of − is + again. For a lineage to survive, the mirror image has to work too. Evolution found two ways to do that. A few genomes became palindromes. Most carry a second, mirrored copy of their own copying machinery, so each strand runs its own. Proved, not just tested

For every one of the 25664 possible partners

Testing 2,012 partners is evidence; a proof covers all of them. For the genome of world 30 we wrote BFF’s rules in Lean 4, together with a second interpreter that treats every partner byte as unknown, and proved that the unknown bytes can never change what happens. The result is one theorem: whatever the partner, the tape ends as the parent followed by the parent reversed.

theorem mirror_copy (B : Vector UInt8 64) :
    run (P ++ B) = P ++ P.reverse

Checked by Lean’s kernel, including the full 8,192-step run (decide +kernel, no native_decide, no sorry; axioms: propext, Quot.sound). The Lean interpreter agrees with our Python and C interpreters on 240 test tapes; that link is tested, not proved.

The intervention

Change one rule and the mirror disappears

Why backwards? In the paper’s version of BFF, both heads start at position 0. The cheapest way to reach the partner is one step to the left, which wraps around to its last byte. Reaching the partner’s first byte instead takes 64 steps to the right. So the cheap copier writes from the partner’s end backwards while it reads itself forwards, and the copy comes out reversed.

Google’s code also has a variant where each program’s first two bytes set where its heads start. A genome can then point its write head straight at the start of its partner. We ran the same experiment under that rule. The prediction: forward copies, one strand, no palindromes.
